# Отчёт о восстановлении

Восстановление выполнено 3 ноября 2026 года. Код и ресурсы извлечены из публичного
APK 0.1.4, найденного по сохранившемуся `remote.origin` прежнего репозитория.
Ветка `main` прежнего репозитория содержала пустое дерево; ветка `android-builds`
содержала APK и сведения о выпуске. Новые данные в GitHub не отправлялись.

| Слой | Восстановленные классы и поведение |

| Панели | Перевод, согласие на ML Kit, оформление, управление, сноски, выбор слова |

| Литературный контекст | `LiteraryReferenceRepository`, `LiteraryIndex`, `LiteraryReference` |
| Хранение | Room: `AppDatabase`, `ReadingDao`, `SavedWord`, `ReadingProgress`, `Bookmark`, `CachedTranslation` |
| Настройки | DataStore Preferences `reading_preferences` |
| Интерфейс | Jetpack Compose, Material 3; `Screens`, `ReaderScreen`, `ReaderSurface`, `Components`, `Theme` |

База называется `greek-reading.db`, версия схемы — 1.
Её таблицы: `progress`, `words`, `translations`, `bookmarks`.
Хеш идентичности Room: `65df098d3c05f2d7b594e082b3147418`.
Схема SQL извлечена из `AppDatabase_Impl` и проверена в отдельной базе SQLite.

Позиции в книге и диапазоны перевода используют Unicode code points.
Compose работает со смещениями UTF-16; преобразования выполняет `UnicodeOffsets`.
Этот контракт нужно сохранить при восстановлении Kotlin.

ML Kit переводит с греческого на русский. Модели загружаются отдельно от APK;
содержимое загруженных на телефоне моделей в этот проект не входит.

## Что нельзя считать исходниками

Java-файлы содержат преобразованные корутины, сгенерированный код Compose,
псевдокод и иногда недопустимые для Java конструкции. Особенно требуют ручной работы:

- `ReaderViewModel.java`
- `core/WordTranslationResolver.java`
- `data/BookRepository.java`
- `ui/ReaderScreenKt.java`
- `ui/ReaderSurfaceKt.java`
- `ui/ScreensKt.java`

Это ограничения представления JADX. Код соответствующих функций не утрачен:
его smali сохранён полностью и прошёл обратную сборку.

`reference/build-config/app.gradle.kts` восстановлен из констант прежнего
кэша Gradle Kotlin DSL. В нём осталась пустая область на месте блока plugins,
который Gradle компилировал отдельно. Версии плагинов восстановлены в
`reference/build-config/root.gradle.kts`. Эти файлы служат справкой для будущего
обычного проекта Android Studio; текущую сборку выполняет Apktool.

Прежние 46 тестов, упомянутые в описании выпуска, не сохранились и здесь не запускались.
Проверки восстановления перечислены в `verification.json`; они не заменяют
проверку поведения на телефоне и тестирование качества перевода ML Kit.

## Как продолжать работу

1. Сохранить эту основу и прежний ключ подписи вне эфемерной среды. Ключ хранить
   отдельно от исходников; его нет в архиве и в Git. Подписанный APK восстановления
   имеет прежние package name, versionCode 5 и versionName 0.1.4.
2. Тексты, сопоставления и оформление редактируются в `apktool-project/assets`
   и `apktool-project/res`. Контрольные суммы глав и обложки в manifest должны
   соответствовать содержимому. Проверка данных намеренно сообщает об их рассогласовании.
3. Точечные изменения логики можно вносить в smali. Декомпилированный Java
   помогает найти нужный класс и функцию. Для стабильных больших изменений удобнее
   восстановить обычный Kotlin-проект.
4. При восстановлении Kotlin сначала перенести `core`, затем Room/DataStore,
   репозитории и переводчик, после них `ReaderViewModel` и Compose. Сохранить
   схему базы и имена файлов Preferences, чтобы установленные данные оставались совместимыми.
   Не добавлять разрушительную миграцию базы ради упрощения восстановления.
5. После переноса каждого слоя сравнивать поведение с APK 0.1.4. В первую очередь:
   границы слов и code points, пагинацию, жесты и удержание, поиск, редактирование
   словаря, восстановление прогресса, границу литературного фрагмента и согласие на ML Kit.
6. Для следующего выпуска согласованно изменить `apktool.yml` и версию, которую
   отображает код приложения. Новую сборку подписывать прежним ключом.

## Проверка сборки

Собранный APK повторно разобран тем же SmaliDecoder из Apktool 3.0.3.
Все 654 файла smali совпали побайтово, включая отладочную информацию.
Содержимое assets, native-библиотек и трёх DEX сторонних зависимостей тоже совпало.

Сравнение таблиц ресурсов учитывало формат упаковки: индексы строкового пула,
флаг PUBLIC, порядок элементов bag по ключам, UTF-8/UTF-16 и избыточные `-vN`
в путях файлов при `N <= minSdk 26`. Идентификаторы, имена и значения совпали.

Проверены SHA-256 глав и обложки, ссылки на абзацы, хеши и границы каждого
литературного фрагмента в code points. Ошибок не найдено.

Подпись и сертификат проверены через `apksigner`, выравнивание — через `zipalign`.
Запуск на Android-устройстве не выполнялся; после установки следует проверить
открытие книги, листание, перевод, словарь и сохранение прогресса.
